# M1. Data layer

**Read first:** `docs/ARCHITECTURE.md` sections 2, 3, 9, 10; `docs/DATA_MODEL.sql`; `docs/DECISIONS.md`; `docs/SPEC.md` sections 4 and 6; `docs/TESTING.md` section 3 (db, settings rows).

**Build**
- [ ] `clock.py`: `Clock` protocol, `SystemClock`, `FakeClock` (settable, advanceable). Honor `TEA_NOW` only when `TEA_DEBUG=1`.
- [ ] `config.py`: paths via `platformdirs` (data, config, state, uploads), constants.
- [ ] `settings.py`: pydantic `Settings` with every field listed in ARCHITECTURE section 9. Load and save JSON in the config dir; unknown keys ignored; invalid values rejected with a clear message. First run seeds interests and region from `data/interests.json`.
- [ ] `db/connection.py`: open DB (WAL, `foreign_keys=ON`), migration runner recording `meta.schema_version`. `migrations/001_initial.sql` is a copy of `docs/DATA_MODEL.sql`.
- [ ] `db/repos.py`: repositories for weeks, blogs, questions, answers, attachments, drafts, handoffs, jobs. Each worker can open its own connection.
- [ ] `domain/weeks.py`: ISO week start, Monday, Thursday and Friday due datetimes from settings, previous-week helper.
- [ ] `logging_setup.py`: rotating file, no content.

**Tests first:** temp-dir DB per test; migrations run twice; every repo method; cascade deletes; week helpers across year ends, leap years and a Monday in late March and late October (no DST assumptions); settings defaults, unknown keys ignored, bad value rejected; `FakeClock`.

**Acceptance**
1. Migrations are idempotent and the schema matches `docs/DATA_MODEL.sql` (a test compares table and column names).
2. All repositories covered by tests, including unique constraints and cascades.
3. Week helpers correct on the edge cases listed.
4. Settings round-trip to disk; first run seeds interests from `data/interests.json`.
5. No `datetime.now()` outside `clock.py` (a test greps `src/`).
