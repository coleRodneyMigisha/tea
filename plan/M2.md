# M2. Hand-off core

Use your most capable model for this milestone. It is the heart of the app: the quality of every draft depends on it.

**Read first:** `docs/SPEC.md` sections 3 and 6; `docs/ARCHITECTURE.md` section 5; `docs/PASTE_FORMAT.md`; `docs/WRITING_STANDARD.md`; `prompts/README.md` and every file in `prompts/`; `docs/TESTING.md` section 3 (handoff rows).

**Build**
- [ ] `handoff/prompts.py`: load `prompts/*.md` and `prompts/blocks/*.md`; parse the header; check the `variables` list against the placeholders in both directions; render; raise on unfilled or unexpected variables; return text, name and version.
- [ ] `handoff/answers.py`: the grouped "my answers" section exactly as ARCHITECTURE section 5 describes (category order, newest per question, skipped excluded, word cap that never drops boundaries answers, `new_answers` since a timestamp).
- [ ] `handoff/packets.py`: `build(kind, ...)` for `weekly`, `weekly_pick`, `manual`, `improve`, `audit`, assembling the optional blocks and collapsing blank-line runs; word count; `prompt_versions`.
- [ ] `handoff/parse.py`: the lenient parser from `docs/PASTE_FORMAT.md`. It never raises.
- [ ] `handoff/importer.py`: `import_reply(handoff_id, text)` as ARCHITECTURE section 5 describes, including pick-mode handling and blog status updates.
- [ ] `handoff/provider.py`: `Provider` protocol and `ManualProvider` stub (the dialog arrives in M7).
- [ ] `devtools/sample_data.py`: sample blogs, answers, one well-formed reply per kind (including a pick-mode reply with candidates), and malformed replies (no tags, no draft tag, no verification, truncated, pipes in claims, unknown statuses, only a draft).
- [ ] CLI: `tea packet` and `tea import-reply FILE` working against a temp or real database.

**Tests first:** everything in `docs/TESTING.md` section 3 for `handoff/prompts`, `answers`, `packets`, `parse` and `importer`.

**Acceptance**
1. All prompts and blocks load, and each header's `variables` equals its placeholders.
2. `tea packet --kind weekly` on sample data prints a complete prompt with no `{{` left and no blank-line runs; `weekly_pick` adds the pick section; `improve` contains the previous draft and only new answers.
3. The parser handles every malformed fixture without raising and produces the warnings listed in `docs/PASTE_FORMAT.md`.
4. Importing the sample pick-mode reply sets the week's focus, the blog topic and title, `topic_origin = auto_trending` and stores the candidates.
5. A packet for a blog with Web and Academic off contains `research_off` and no mention of searching.
6. Read three rendered packets (weekly, pick, improve) in full and report anything that reads badly or contradicts `docs/WRITING_STANDARD.md`.
